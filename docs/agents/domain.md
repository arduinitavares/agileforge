# Domain documentation

AgileForge uses one domain context for this repository.

Before exploring a domain area, read the root [CONTEXT.md](../../CONTEXT.md) and the relevant decisions in [docs/adr/](../adr/). Use the glossary's terms in issue reports, specifications, code, and tests. If a proposed change conflicts with an ADR, identify the conflict before changing the decision.

If a referenced domain document is absent, continue without requiring a placeholder. Create or update domain documentation when the work resolves an actual term or decision.

Keep the existing root glossary and ADR layout. A `CONTEXT-MAP.md` or per-package context hierarchy is not required.
