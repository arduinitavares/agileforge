Keep the SDD ledger/review packages outside the repository; git remains read-only. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An accepted prerequisite replacement must reopen dependency review instead of letting an obsolete Story identity either block planning or satisfy dependency authority.

**Architecture:** Keep SQLite and the existing correction/review transactions. Append targeted prerequisite-supersession anchors in `workflow_events` inside accepted Story replacement; fold their immutable identity into the projected scope token, preserving its v1 value when there is no relevant invalidation. Current authority stops at live Done/Accepted external prerequisites; their outgoing historical edges do not require downstream repair. Already-stale rows use an implicit anchor based on the superseded source artifact, with successor proof when identifiable; human reconciliation adopts anchors before changing the graph, including affected unselected roots. Only human review rejects the old edge or approves a new one, and stored Sprint evidence remains pinned.

**Tech Stack:** Existing Python 3.13, SQLModel/SQLite, Pydantic, workflow graph, pytest, and uv. No dependency addition, storage migration, or frontend implementation.

**Spec:** The phase-1 request and [issue #188](https://github.com/arduinitavares/agileforge/issues/188), including its P0/ready triage, plus the orchestrator's phase-2 approval are binding. Re-review resolved all five original findings and confirmed both qualifications. Approved choices remain targeted atomic invalidation/adoption without migration, opaque scope-token expansion with unchanged no-anchor v1 values, and actionable-only inspect issues. This execution revision defines one terminal predicate, explicitly changes non-supersession traversal, and excludes stale accepted/planned Sprint recovery.

## Designs considered

| Design | Assessment |
| --- | --- |
| Append an invalidation event during Story acceptance, with a per-dependent revision | **Chosen.** Precise affected scopes and a revision independent of the subsequent approved edge set. Adds one typed audit event and verified compatibility/adoption for already-stale rows; fits the existing append-only event pattern without new tables/columns. |
| Introduce a distinct dependency-review source token and new API/CLI guard field | Viable and semantically explicit. Requires propagation through requests, replay payloads, projections, review matching, and execution-source handling, which currently share `selected_scope_fingerprint`. Keep as an alternative if reviewers reject broadening the existing token. |
| Use a Project-wide accepted-supersession revision | Viable and stable after review, with no new event writes. It invalidates unrelated selected scopes after any accepted Story correction, so the chosen targeted markers have a narrower authority impact. |
| Derive revision solely from retained dependency graph/history | Rejected after design check: approving B->C can expose C's rejected history to superseded D and change the source immediately after Apply. A token dependent on that changing footprint cannot reliably bind one renewed review. |

Dropping obsolete edges from planning while retaining the old approval would silently remove a human-approved dependency. Automatic B->C retargeting is prohibited. Migrating graph storage does not supply an approval policy. None is an acceptable repair.

## Chosen design and invariants

### Stable scope revision and atomic invalidation

Keep `selected_scope_fingerprint(project_id=..., stories=...)` and its `agileforge.story-selected-scope.v1` payload as the base hash. Create `services/story_dependency_lifecycle.py`, following the existing typed append-only event pattern in `services/story_sprint_selection.py`. This module must not import Story acceptance or the dependency-review writer; both callers may import it without a cycle.

Define `StoryDependencyInvalidationAnchor(FrozenModel)` with required `dependent_story_id`, `superseded_story_id`, `superseded_story_artifact_id`, and `superseded_story_artifact_fingerprint`. These four fields alone are the canonical freshness identity. Paired optional `replacement_story_artifact_id` / `replacement_story_artifact_fingerprint` supply accepted-successor diagnostics when proven; normal acceptance always supplies them. An anchor requires review of the old identity, without approving or mapping a replacement Story. One accepted artifact can supersede several old Stories and materialize several new Stories. Discovering successor diagnostics later must not change the identity, duplicate an anchor, or revise a renewed source.

Define `StoryDependencyInvalidationPath(FrozenModel)` with `dependent_story_id`, `superseded_story_id`, and `dependency_rows: tuple[StoryDependencyFact, ...]` in path order. Define `StoryDependencyInvalidationMetadata(FrozenModel)` with `schema_version="agileforge.story-dependency-invalidation.v1"`, `action="story_dependency_invalidated"`, `mode="accepted_replacement"|"review_adoption"`, canonical `anchors`, and canonical `causal_paths: tuple[StoryDependencyInvalidationPath, ...]`. Paths capture IDs/endpoints and the active/proposed state observed at invalidation; one deterministic simple path suffices to prove each root-to-obsolete-endpoint reachability. Persist using a new `WorkflowEventType.STORY_DEPENDENCY_STALE = "story_dependency_stale"`, `sprint_id=None`, and the existing metadata column. No new table, column, index, or migration is planned. Verify enum compatibility with the existing SQLite column/manifest in Task 1; do not assume either outcome without the schema gate.

Both inference and persistence reconstruct/verify causal paths from the caller's current rows before reconciliation changes them; anchor identity is independent of path serialization and optional successor diagnostics. `StoryDependencyLifecycleIntegrityError` is reserved for corrupt evidence: malformed/foreign IDs, source fingerprints that contradict stored artifacts, invalid persisted metadata, or contradictory/cyclic lineage actually encountered during proof. Repository loading translates corruption to its existing fact-load error; the writer translates it to its structured graph error. A superseded source with no identifiable accepted successor is an unresolved dependency, not this error.

- During accepted replacement, capture prior Story rows and traverse the reverse current `active`/`proposed` graph to live non-terminal dependents, selected or unselected. Use `is_terminal_external` below: never anchor a terminal dependent or propagate through it, regardless of Sprint membership. Stop through superseded dependents (including this acceptance's superseded set) and completed-Sprint members. A separately superseded B is its own obsolete target for D->B; D must not inherit an A anchor through superseded B->A history. Use a visited set for cycles/diamonds; ignore unrelated/rejected branches.
- Append one canonical event for the affected anchor set inside the existing caller-owned acceptance transaction, alongside supersession/materialization/structural validation. If any acceptance step fails, all these writes roll back. No event for draft, feedback, rejected replacement, or accepted replacement with no affected current edges. Replaying acceptance must not append another event.
- Verify loaded event Project ownership, canonical metadata, dependent identities, saved causal paths, and exact superseded source-artifact identity. When successor diagnostics are present, verify their accepted decision and ancestry. An `accepted_replacement` event requires that proof; a `review_adoption` event may carry a source-only anchor. Historical causal paths are checked as saved evidence, not required to remain live/actionable after completion, reconciliation, or later correction. Edge endpoint identities are evidence; later status/reason changes are allowed. Adoption records the present reconciliation, not a fabricated past acceptance event.
- The pure token function selects only anchors targeted at selected Story IDs. No selected IDs/relevant anchors: return the v1 base unchanged. Otherwise hash `{schema_version: "agileforge.story-selected-scope.v2", selected_story_scope_fingerprint: base, invalidation_anchors: canonical anchor identities}`. Exclude optional successor diagnostics, event IDs/timestamps, causal paths, current graph/status/reason, and mutable completion status. Persisted anchors remain stable after their graph path ceases to be current.
- The repository folds persisted and verified implicit anchors into one canonical set and attaches the final token consistently to every `StoryFact.selected_scope_fingerprint`. Inspect, dependency source references, application stale guards, candidate-set fingerprints, and new Sprint evidence consume it.
- Unrelated corrections and later supersession on a rejected relationship do not revise B's token. Adding an approved B->C whose rejected history includes obsolete D must not import that history into B's invalidation revision. A later accepted C replacement does target B if B->C is then current.

### Already-stale current-schema rows

An old B->A edge may predate the new event. First compute the actionable selected active/proposed closure using already-loaded Story/dependency identities and completion facts. If it contains no superseded prerequisite, return without invoking the new inference's artifact/decision queries or lineage builder. Persisted-marker validation is separate from this gate.

For each obsolete endpoint, verify the old Story's exact source artifact and fingerprint, then attempt accepted-descendant proof using `build_story_artifact_lineage_nodes` and existing lineage validation. Prefer the **first accepted descendant that superseded the exact old artifact**, including transitive chains with intervening drafts/feedback/rejection. Never choose a moving latest leaf. If otherwise valid legacy evidence does not identify that descendant, retain the four-field source-only anchor: B remains unsafe and review is required, while workflow next/inspect/planning fact loading continues. Do not swallow actual malformed/contradictory evidence as an inference miss. Normalize one canonical identity per affected root/old Story. If an identity is already persisted, inferred successor diagnostics may enrich that same returned anchor without another anchor/event or token change; only genuinely missing identities require adoption. Keep stored event metadata append-only. Reads/inspect never write.

Human Apply adopts implicit anchors in its caller transaction before changing old edges. Calculate affected live reverse ancestors of every obsolete path that the mutation can remove, using the same completion boundary; adopt their pre-mutation anchors **including unselected roots**. Thus reviewing external X->A in X's scope cannot erase B's implicit B->X->A epoch while B is unselected. This append changes no edge owned by B and grants no approval. The selected scope's normalized persisted identity equals its previously inferred identity, so renewal stays current after B->A disappears. Failed Apply rolls back adoption and review/edge/event writes; exact replay appends nothing. Normally recorded acceptance needs no adoption.

**Trade-off:** this adds a small audit authority and a compatibility rule, rather than coupling freshness to mutable edges. Proof/normalization and rollback tests are essential. It preserves both local invalidation and stable human approval without new mutation request fields.

**Actionability:** callers supply live non-terminal roots as defined below. Review/readiness restrict roots to the selected scope; inspection/adoption may include unselected roots that can become eligible. Completed-Sprint membership retains its existing exclusion. Inspect is not limited to today's selection.

**Single terminal definition:** `is_terminal_external(story)` is true exactly when the Story is not superseded and its status is `Done` or `Accepted`. This is independent of selected-root identity and Sprint membership. Superseded endpoint classification precedes this predicate: direct B->A with superseded Done A still requires human review. Define all traversal/diagnostic/invalidation/adoption roots as live, non-superseded, **non-terminal** Stories that can become selection-eligible; also preserve the existing exclusion of completed-Sprint membership. Unselected or currently awaiting structural validation Stories may be roots, but Done X is never a root, even with no Sprint membership. Persisted human selection/evidence remains unchanged.

**Completed membership is retained history, not terminal status:** pass the same completed-Story ID set into every current traversal, prospective writer cycle/obsolete check, invalidation/inference/adoption and inspection. Exclude those roots and stop before their outgoing history, even when X is unfinished. Retain incoming B->X; unfinished X still gives the legitimate incomplete-X blocker. Classify a superseded incoming prerequisite before this stop, so direct B->superseded A remains actionable even if A had completed membership. This preserves the already-required membership exclusion without redefining `is_terminal_external`. Add B->X(unfinished, completed Sprint)->A regression: A replacement creates no B anchor/token change or obsolete-review deadlock; B can retain B->X and waits only for X.

Scan roots and canonicalize the union. Keep each incoming active/proposed row and validate endpoint identity. If the prerequisite is superseded, report it and stop; otherwise if `is_terminal_external(prerequisite)`, retain the incoming edge and stop. Never inspect terminal X's outgoing history as actionable. Use the same predicate at all five sites: `_story_readiness_blockers`, `_selected_dependency_safety`, `_dependency_problem`, acceptance-time reverse invalidation, and review-time adoption. Inspection/inference also consume this shared policy, without a second status/membership-based terminal definition.

**Intentional non-supersession change, qualified by B1:** B->X(terminal)->Y(incomplete) no longer blocks B solely on Y. Terminal history remains excluded from per-Story dependency safety and actionable obsolete issues. Sprint planning and starting additionally require an acyclic full active Project graph, matching execution; a retained cycle behind terminal X yields `STORY_DEPENDENCY_CYCLE` before a Sprint can be planned or started. Apply separately rejects a full prospective cycle containing a submitted reviewed pair, without auto-removing retained edges. Full historical snapshots/closure remain unchanged.

The obsolete query uses active/proposed traversal and returns only rows with a superseded prerequisite reached from these live roots. Superseded-dependent rows, rejected rows, and rows behind a terminal external boundary remain historical `edges`, without issues. Current active-closure completion/safety checks, obsolete diagnostics, and reverse invalidation/adoption share this boundary. Full prospective review cycle validation and the Sprint-level full active Project cycle barrier are separate checks matching execution. Proposals still require human approval; their inclusion for supersession detection does not make them active authority. Preserve endpoint/canonicality validation for reached rows and existing whole-Project fact integrity checks; do not excuse corrupt ownership or genuine actionable cycles as supersession.

- Accepted replacement leaves the durable B->A row intact for inspection. It is unresolved current authority, not an executable prerequisite whose old status can satisfy or block readiness.
- For an otherwise valid unlocked selected scope with obsolete endpoints, `planning.story_dependencies` becomes `AVAILABLE / STORY_DEPENDENCY_REVIEW_REQUIRED`, with blocker `STORY_DEPENDENCY_SUPERSEDED_ENDPOINT`. Sprint planning remains gated on human review, with that obsolete-endpoint reason instead of old A's incomplete-status reason.
- `_story_readiness_blockers`, `_selected_dependency_safety`, and `_dependency_problem` must use the current boundary and check obsolete authority before completion status. Direct B->A keeps B unsafe/non-candidate even when superseded A was Done/Accepted. B->X(Done/Accepted, completed Sprint)->A keeps B->X legitimate, without importing X's historical outgoing blockers/cycles/obsolete authority. Historical closure and stored Sprint snapshots remain full and unchanged.
- Preserve the existing review locks for accepted/planned Sprints, active Sprints, retry state, and untriaged completed Sprints. A supersession diagnostic must not bypass them.
- The human can submit an exact edge set that excludes B->A, or explicitly approves B->C. Existing `apply_story_dependencies_in_session` rejects omitted old rows and accepts only exact active endpoint identities. It must still reject attempts to approve B->A. Validate the prospective selected active graph (existing rows with selected dependents' edge sets replaced by the request) before committing: a newly added B->C cannot approve an actionable obsolete active/proposed closure behind C. A non-superseded Done/Accepted C uses the same terminal predicate; rejected history behind C is not unresolved authority.
- For B->X->A with X incomplete and selectable, expose X->A; human review can reconcile X in an eligible scope before renewing B. Resubmitting B->X while that actionable obsolete closure remains cannot make B safe. The human may explicitly exclude B->X, but exclusion is never required merely because completed X retains X->A history. For terminal external X, do not anchor B through X or demand repair of X->A; B can retain/review B->X. Do not silently mutate an external dependent's edge set.
- A fresh review uses the revised source, coexists with the old review under the existing uniqueness constraint, and stays current after reconciliation. Old reviewed-edge JSON, reviewer/time, IDs, receipts, and Sprint pins are unchanged.
